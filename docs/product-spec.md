# 메추리

> 이 문서는 장기 제품 기획서다. 해커톤 1차 구현의 기준은 `plan.md`이며, 충돌하면 `plan.md`가 우선한다. 이 문서에서 해커톤 범위 밖인 항목은 `plan.md` §12에 정리되어 있다. 구현 중 이 문서만 보고 기능을 추가하지 않는다.

## 한 줄 소개
연세대 국제캠퍼스 학생들이 각자 꼽은 맛집 순위와 태그를 모아 만든, 지역 맛집 지도 겸 메뉴 추천 서비스.

## 사용자와 사용 맥락
- 주 사용자: 연세대 국제캠퍼스(송도) 재학생
- 사용 빈도·시점: 식사 직전(11–13시, 17–20시, 야식 21–01시). 세션당 1–3분
- 사용 환경: 모바일 브라우저가 대부분. 동시 편집 이슈 없음(개인 리스트는 본인만 수정)
- 사용자 수 규모: 초기 수십–수백 명, 목표 1,000명 내외. 음식점 수 수백 곳
- 확장: 추후 타 지역으로 확장 [명시] → 처음부터 "지역(Region)" 단위로 데이터 분리

## 화면 구조
```
[비로그인 진입] ─→ 순위 탭(열람 전용) ─→ 로그인 유도
[회원가입: 아이디·비밀번호] → 온보딩: 내 맛집 Top 3 + 가게별 취향 정보 입력(보상 표시)
하단 탭
├─ 순위 (지도/리스트 토글)   : 음식 종류·맛 스타일·분위기·상황·가격대·평가 필터별 순위. 지도에는 순위 핀
│   ├─ 필터 시트             : 태그 그룹별 칩 선택
│   └─ 음식점 상세           : 순위, 언급 수, 태그·평가 분포, 카카오맵 링크
│       └─ 간단 리뷰 시트    : 태그 칩 선택형 리뷰 작성·수정
├─ 추천 (잠금 가능)          : 무료 주 1회 개인화 추천(1곳) / 프리미엄 무제한 / 포인트로 추가 추천
│   └─ 잠금 화면             : Top 3 미입력 시 입력 유도
├─ 내 맛집                   : 내 순위 리스트(3–10개) 편집, 취향 분석, 내가 쓴 리뷰
└─ 마이                      : 계정, 구독(모의 결제), 포인트 잔액·내역
```
- Top 3 미입력자: 순위 탭만 사용 가능, 추천 탭 진입 시 잠금 화면, 매 세션 입력 유도 모달 [명시]
- "맛집 지도"와 "순위"는 같은 데이터의 두 뷰이므로 하나의 탭으로 통합 [결정]

## 기능 명세

### A. 계정·온보딩

#### F-01 가입·로그인 (MVP: 아이디·비밀번호)  [명시]
**동작**: 아이디와 비밀번호만 입력하면 가입·로그인된다. 학교 이메일 인증, 소셜 로그인 등 다른 절차는 MVP에서 전부 생략한다.
**세부 요구사항**:
- 가입 입력: 아이디, 비밀번호, 비밀번호 확인. 이 3개 외 입력 없음
- 아이디: 4–20자, 영문 소문자·숫자·밑줄(_). 대소문자 구분 없음(소문자로 정규화). 중복 시 즉시 "이미 사용 중인 아이디" 표시
- 비밀번호: 8자 이상. 저장·해시는 Supabase Auth가 담당(auth.users, bcrypt). 우리 테이블에는 비밀번호 열이 없다
- 가입 즉시 로그인 상태로 온보딩(F-02) 진입
- 로그인 유지: 30일. 로그아웃은 마이 탭
- 로그인 5회 연속 실패 시 해당 아이디 5분 잠금 [이후 — Supabase Auth 기본 기능은 IP 단위 빈도 제한뿐이라 계정 단위 잠금은 별도 구현 필요]
- 가입 빈도 제한: 동일 IP 시간당 5계정 [결정 — 인증이 없으므로 다계정 순위 조작에 대한 최소 방어]
- 비밀번호 찾기: 없음. 분실 시 관리자에게 문의 → 관리자가 임시 비밀번호 발급(F-16) [결정 — 이메일·전화 수집을 안 하므로 자동 복구 수단이 없음]
- 비로그인도 순위 탭 열람 가능 [결정 — D-4]
- 이후 단계: 학교 이메일 인증, 카카오 로그인 추가(D-5)
**완료 조건**:
- [ ] 아이디·비밀번호·확인 3개만 입력하고 가입하면 바로 온보딩 화면이 뜬다
- [ ] "Soono"와 "soono"는 같은 아이디로 취급되어 두 번째 가입이 거부된다
- [ ] 우리 테이블 어디에도 비밀번호 열이 없고, Supabase Authentication → Users에 `아이디@users.mechuri.app` 계정이 생긴다
- [ ] 같은 아이디로 5회 틀리면 6번째 시도는 올바른 비밀번호여도 5분간 거부된다
- [ ] 비로그인 상태에서 순위 탭의 필터와 음식점 상세가 동작한다

#### F-02 온보딩: 내 맛집 Top 3 + 취향 정보 입력  [명시]
**동작**: 가입 직후 내 맛집 Top 3를 고르고, 가게마다 음식 종류·맛 스타일·분위기·상황 등 정보를 칩으로 입력한다. 정보를 많이 넣을수록 보상이 커지는 것이 화면에 실시간으로 보인다. 목적은 첫 입력 단계에서 받는 정보 개수를 최대화하는 것이다.
**세부 요구사항**:
- 1단계: 가게 검색·선택(F-05 컴포넌트) 3곳, 드래그로 1·2·3위 지정. 3곳 채우기 전까지 다음 버튼 비활성
- 2단계: 가게별 정보 카드. 구성은 간단 리뷰 시트(F-18)와 동일, 한 화면에 한 가게씩, 좌우 스와이프로 이동
  - 가게마다 "건너뛰기" 가능. 건너뛴 가게는 보상 없음
- 진행 표시(화면 상단 고정)
  - "입력한 정보 N개" (선택한 칩 총개수)
  - 취향 완성도 = 정보가 1개 이상 입력된 (가게, 그룹) 쌍 수 / (가게 수 × 활성 그룹 수), 백분율 [결정]
  - 칩을 누를 때마다 획득 예정 포인트가 즉시 갱신("+1P", "+1P 풍부 보너스")
- 보상(상세 규칙은 F-20)
  - 가게별 기본 적립 조건(2개 그룹 이상, 칩 3개 이상) 충족 시 1P, 리뷰 3건 미만 가게면 2P
  - 가게별 풍부 보너스: 5개 그룹 이상 입력 시 +1P
  - 온보딩 완주 보너스: Top 3 전부 기본 적립 조건 충족 시 +3P
  - 온보딩 중 적립분은 주간 한도(10P) 미적용
- 3단계: 완료 화면. 획득 포인트 합계 + "첫 개인화 추천 받기" 버튼(F-11) + "맛집 더 추가하기(최대 10곳)" 버튼
  - 4–10번째 가게 추가 시에도 동일한 정보 카드와 적립 규칙(이때부터는 주간 한도 적용)
- 온보딩 전체 건너뛰기 가능 → F-04의 제한 상태로 진입
**완료 조건**:
- [ ] 2곳만 선택한 상태에서 다음 버튼이 비활성이다
- [ ] 칩을 선택할 때마다 "입력한 정보 N개"와 획득 예정 포인트가 즉시 바뀐다
- [ ] Top 3 모두 조건을 채우고 완료하면 가게별 적립 + 3P가 한꺼번에 들어오고 원장에 각각 기록된다
- [ ] Top 3 저장 즉시 추천 탭 잠금이 해제된다
- [ ] 건너뛰면 순위 탭으로 이동하고 입력 유도 배너가 보인다

#### F-03 내 맛집 리스트 편집  [명시]
**동작**: 내 맛집 탭에서 리스트를 추가·삭제·순서 변경한다. 저장하면 전체 순위에 반영된다.
**세부 요구사항**:
- 최소 3개, 최대 10개. 10개 상태에서 추가 버튼 비활성
- 순서 변경: 드래그 앤 드롭 + 위/아래 버튼(접근성)
- 3개 미만으로 삭제 시도 시 "최소 3개 유지" 경고 후 차단. 교체는 편집 모드 저장 시점 기준으로 검사
- 같은 음식점 중복 불가
- 편집은 "편집 모드 → 저장" 방식. 저장 전 이탈 시 변경 폐기 확인 다이얼로그
- 가게를 새로 추가하면 정보 카드(F-18 시트)가 이어서 뜬다(건너뛰기 가능)
- 저장 빈도 제한: 계정당 하루 10회 [결정]
- 폐업 처리된 음식점이 리스트에 있으면 회색 표시 + "폐업 — 교체해주세요", 순위 계산에서 제외
**완료 조건**:
- [ ] 순서를 바꾸고 저장하면 전체 순위 점수가 재계산된다
- [ ] 11번째 추가가 불가능하다
- [ ] 3개인 상태에서 1개 삭제 후 저장하면 저장이 거부된다

#### F-04 미입력자 제한 및 입력 유도 알림  [명시]
**동작**: Top 3를 입력하지 않은 사용자는 순위 탭만 쓸 수 있고, 입력하라는 알림이 계속 뜬다.
**세부 요구사항**:
- 추천 탭: 잠금 화면(설명 + "내 맛집 입력하기" 버튼 + "입력하면 최대 N P" 보상 안내). 추천 API는 서버에서도 차단
- 내 맛집 탭: 입력 화면 그 자체로 표시
- 알림 방식
  - 세션 시작마다 입력 유도 모달 1회(닫기 가능) [결정 — "계속 뜸"을 세션당 1회로 해석]
  - 순위 탭 상단 고정 배너(닫기 불가)
  - 음식점 상세 하단에 "이 집 좋아하면 내 맛집에 추가" 버튼
- 웹 푸시 알림은 쓰지 않음 [결정 — iOS는 설치된 PWA에서만 웹 푸시 가능]
**완료 조건**:
- [ ] 미입력 상태로 앱을 새로 열 때마다 모달이 1회 뜬다
- [ ] 미입력 상태에서 추천 API를 직접 호출하면 403을 받는다
- [ ] Top 3 저장 후에는 모달·배너가 더 이상 표시되지 않는다

### B. 음식점 데이터

#### F-05 음식점 검색·불러오기  [명시: "지도 앱에서 정보 불러오기"]
**동작**: 검색창에 가게 이름을 치면 카카오 로컬 API 결과가 뜨고, 선택하면 메추리 음식점 DB에 연결된다.
**세부 요구사항**:
- 카카오 로컬 키워드 검색, 서비스 지역 범위(F-06) 내로 좌표 제한, 음식점(FD6)·카페(CE7) 그룹만
- 결과 항목: 이름, 주소, 카카오 카테고리 문자열, 거리
- DB에 이미 있으면 기존 Place에 연결, 없으면 신규 Place 생성 → 자동 분류(F-07) → 관리자 검수 큐
- 서비스 지역 밖 가게 선택 시 "메추리 서비스 지역 밖 가게예요" 안내 후 차단
- 검색 결과 0건: "카카오맵에 없는 가게는 등록할 수 없어요" 안내
**완료 조건**:
- [ ] 국캠 인근 가게 이름 검색 시 1초 내 결과가 뜬다
- [ ] 처음 등록된 가게는 관리자 검수 큐에 나타난다
- [ ] 서비스 지역 밖 좌표의 가게는 저장이 거부된다
**열린 질문**: D-1 참조

#### F-06 서비스 지역(Region)  [추론]
**동작**: 모든 음식점·순위·사용자는 지역에 속한다. 최초 지역은 "연세대 국제캠퍼스".
**세부 요구사항**:
- Region: 이름, 중심 좌표, 반경, 인증 이메일 도메인 목록(이후 단계용, MVP 미사용)
- 최초 값: 국제캠퍼스 중심 반경 3 km [결정]
- 순위는 지역별로 독립 계산
- 확장 시 Region 행만 추가하면 동작하도록 하드코딩 금지
**완료 조건**:
- [ ] Region 테이블에 새 지역을 추가하면 코드 수정 없이 해당 지역 순위 페이지가 생긴다

#### F-07 음식 종류 분류 (관리자 전처리 + 사용자 입력)  [명시]
**동작**: 모든 음식점에 대분류(한식·중식·양식 등)와 소분류가 미리 붙어 있고, 사용자도 정보 입력·리뷰에서 음식 종류를 고를 수 있다. 사용자 입력은 빈칸을 채우고 오분류를 바로잡는 데 쓰인다.
**세부 요구사항**:
- 자체 분류표(2단계)
  | 대분류 | 소분류 |
  |---|---|
  | 한식 | 국밥·해장국, 찌개·백반, 고기·구이, 면·칼국수, 족발·보쌈, 찜·탕, 한정식 |
  | 중식 | 짜장·짬뽕, 마라, 양꼬치, 딤섬 |
  | 일식 | 돈까스, 초밥·회, 라멘·우동, 덮밥, 이자카야 요리 |
  | 양식 | 파스타, 스테이크, 브런치, 리조또 |
  | 아시안 | 쌀국수, 태국, 인도·커리, 멕시칸 |
  | 분식 | 떡볶이, 김밥, 라면, 튀김 |
  | 치킨 | 후라이드·양념, 구이 |
  | 버거·피자 | 버거, 피자, 샌드위치 |
  | 샐러드·건강식 | 샐러드, 포케 |
  | 카페·디저트 | 커피, 베이커리, 디저트 |
  | 술집 | 호프, 이자카야, 포차, 와인바 |
- 자동 분류: 카카오 `category_name`의 2·3단계 문자열 → 매핑 규칙 테이블. 매핑 실패 시 "기타" + 관리자 큐
- 초기 적재: 오픈 전 반경 내 음식점 일괄 수집 → 자동 분류 → 전수 수동 검수 [결정]
- 사용자 입력: 정보 카드·리뷰 시트에서 소분류 최대 2개 선택(선택 시 대분류 자동 결정)
- 최종 분류 우선순위: 관리자 수동값 > (자동값 ∪ 사용자 선택 중 F-19 기준 통과 소분류) [결정]
  - 가게당 소분류 최대 3개

### C. 순위

#### F-08 전체 순위 산출  [명시]
**동작**: 모든 사용자의 내 맛집 리스트를 합산해 지역별 음식점 순위를 만든다. 사용자가 리스트를 바꾸면 순위도 갱신된다.
**세부 요구사항**:
- 위치 가중치 w(r) = 1 / log₂(r + 1)  → w(1)=1.00, w(2)=0.631, w(3)=0.500, w(10)=0.289
- 원점수 S(p) = Σ_u w(r_u(p))
- 보정 점수 S̃(p) = S(p) · n_p / (n_p + m),  n_p = p를 꼽은 사용자 수, m = 2 [결정]
- 순위 노출 최소 조건 n_p ≥ 2. 미달 가게는 "신규 발견" 섹션
- 폐업 가게·정지 계정의 표 제외
- 리스트 저장 시 즉시 재계산 [결정]
- 동점: n_p 큰 순 → 1위 표 수 많은 순 → 이름순
**완료 조건**:
- [ ] 테스트 데이터(사용자 3명)로 계산한 점수가 수식과 소수점 셋째 자리까지 일치한다
- [ ] 한 명만 꼽은 가게는 순위 리스트에 없고 "신규 발견"에만 있다
- [ ] 리스트 저장 직후 순위 탭 새로고침 시 변경이 반영된다

#### F-09 순위 탭: 필터·지도/리스트  [명시]
**동작**: 음식 종류, 맛 스타일, 분위기, 상황, 가격대, 평가 항목을 골라 해당 조건의 순위 리스트와 지도를 본다. 이것이 무료 메뉴 추천이다.
**세부 요구사항**:

- 태그 필터 판정은 F-19 기준. 태그 데이터가 부족해 제외된 가게 수를 결과 하단에 "리뷰가 부족해 제외된 가게 N곳 — 정보 남기기"로 표시
- 순위는 전체 점수 S̃로 필터 후 재정렬
- 필터 UI: 상단에 음식 종류 칩 가로 스크롤, 나머지는 "필터" 버튼 → 바텀 시트. 적용 필터 수 뱃지
- 리스트 카드: 순위, 이름, 대·소분류, 언급 수 n_p, 메추리 픽 메뉴, 거리, 부여된 태그 최대 3개

- 필터 상태는 URL 쿼리에 반영
- 빈 결과: "이 조건에 순위가 매겨진 가게가 아직 없어요" + 신규 발견 섹션
**완료 조건**:
- [ ] 맛{매운, 얼큰한} + 상황{데이트} 선택 시 결과의 모든 가게가 두 조건을 만족한다
- [ ] 필터가 걸린 URL을 새 창에서 열면 같은 결과가 나온다
- [ ] 지도·리스트 토글 시 필터가 유지된다
- [ ] 화면 어디에도 배달 필터·뱃지가 없다

#### F-18 간단 리뷰(선택형)  [명시]
**동작**: 사용자가 태그 칩을 눌러 30초 안에 리뷰를 남긴다. 텍스트 입력은 없다. 온보딩 정보 카드(F-02)도 같은 데이터로 저장된다.
**세부 요구사항**:
- 작성 자격: 로그인 사용자. 서비스 지역 내 모든 음식점 대상(내 맛집 여부 무관)
- 1인 1가게 1리뷰, 재작성은 수정(upsert)
- UI: 바텀 시트, 그룹별 칩 한 화면. 평가형은 3단 세그먼트. 모든 그룹 선택 사항. 상단에 "선택 N개 · +N P 예정" 표시
- 제출 최소 조건: 1개 이상 선택
- 진입점: 음식점 상세 / 내 맛집 추가 직후 / 추천 결과 카드의 "가봤어요"
- 작성 한도: 계정당 하루 20건 [결정]
- 삭제 가능, 삭제 시 집계에서 즉시 제외
**완료 조건**:
- [ ] 아무것도 선택하지 않으면 제출 버튼이 비활성이다
- [ ] 같은 가게에 다시 리뷰를 쓰면 기존 리뷰가 바뀐다
- [ ] 맛 스타일에서 4번째 칩을 누르면 선택되지 않고 "최대 3개" 안내가 뜬다
- [ ] 21번째 리뷰 제출은 거부된다(당일 KST 기준)

#### F-19 태그 집계·부여 기준  [추론]
**동작**: 리뷰를 모아 가게마다 어떤 태그가 붙는지 판정한다. 필터·추천·음식 종류 보정(F-07)이 이 판정을 쓴다.
**세부 요구사항**:
- 윌슨 점수 구간 하한(95%, z = 1.96)
  LB(k, n) = [ p̂ + z²/(2n) − z·√( p̂(1−p̂)/n + z²/(4n²) ) ] / (1 + z²/n),  p̂ = k/n
- 서술형 태그: n = 해당 그룹에 1개 이상 선택한 리뷰 수, k = 그 태그 선택 수. LB ≥ 0.30이면 부여
  (2/2 → 0.342 부여, 1/1 → 0.207 미부여, 4/10 → 0.168 미부여)
- 평가형 긍정 필터: n = 응답 수, k = +1 응답 수. LB ≥ 0.40이면 통과 (3/3 → 0.438 통과, 5/8 → 0.306 미통과)
- 평가형 표시: 응답 수 ≥ 3일 때 분포 막대. 부정 뱃지 없음(D-7)
- 리뷰 작성·수정·삭제 시 해당 가게만 즉시 재계산, PlaceTagStat 캐시
- 정지 계정 리뷰 제외
**완료 조건**:
- [ ] "매운" 선택 2/2인 가게는 "매운" 필터에 포함되고, 1/1인 가게는 제외된다
- [ ] 리뷰 삭제 직후 해당 가게의 태그 판정이 갱신된다
- [ ] 고정 테스트 데이터에서 LB 값이 수식과 소수점 셋째 자리까지 일치한다

#### F-20 정보 입력·리뷰 보상  [명시]
**동작**: 정보를 입력하거나 리뷰를 남기면 포인트를 받고, 포인트로 추가 개인화 추천을 받는다. 보상은 "더 많은 정보"에 비례하게 설계한다.
**세부 요구사항**:
- 적립 규칙(가게당 최초 리뷰 기준, 수정·삭제 후 재작성은 적립 없음)
  | 항목 | 조건 | 포인트 |
  |---|---|---|
  | 기본 | 2개 그룹 이상, 칩 3개 이상 | 1P |
  | 개척 | 기본 충족 + 제출 시점 그 가게 리뷰 < 3건 | 기본 대신 2P |
  | 풍부 보너스 | 5개 그룹 이상 입력 | +1P |
  | 온보딩 완주 | Top 3 전부 기본 충족 | +3P (1회) |
- 가게 1곳 최대 3P(개척 2P + 풍부 1P)
- 주간 한도: 10P(월–일 KST). 가입 후 첫 온보딩 흐름의 적립분은 한도 미적용
- 사용처: 3P = 추가 개인화 추천 1회(F-11 주간 한도와 별도)
- 원장(ledger) 방식. 적립·사용·회수 모두 한 줄씩 기록, 잔액 = 합계
- 회수: 적립 후 7일 이내 리뷰 삭제 시 회수. 잔액 부족 시 다음 적립에서 상계(음수 잔액 없음)
- 계정 정지 시 잔액 소멸
- 제출 완료 화면: "+N P (잔액 N P · 추가 추천까지 M P)"
**완료 조건**:
- [ ] 한 그룹에서만 3개 고른 리뷰는 제출되지만 포인트는 0이다
- [ ] 리뷰 1건인 가게에 5개 그룹을 채운 리뷰를 쓰면 3P가 적립된다
- [ ] 온보딩에서 Top 3 전부 조건을 채우면 완주 보너스 3P가 추가되고, 온보딩 적립분이 10P를 넘어도 전액 적립된다
- [ ] 온보딩 이후 같은 주에 10P를 채우면 추가 리뷰는 적립되지 않는다
- [ ] 3P로 추가 추천을 실행하면 잔액이 3 줄고 원장에 사용 내역이 남는다

### E. 추천

#### F-11 무료 개인화 추천 (1곳)  [명시]
**동작**: Top 3 이상 입력한 사용자는 주 1회 개인화 추천 1곳을 받는다. 가입 직후 첫 추천을 바로 받을 수 있다.
**세부 요구사항**:

- 사용 후: "다음 추천까지 N일" + "3P로 한 번 더" + 프리미엄 안내

#### F-13 추천 알고리즘  [추론 — "취향 분석 후 개인화"]
**동작**: 내 리스트와 다른 사용자 리스트의 동시 출현, 내 태그 취향, 전체 인기를 섞어 점수를 매긴다.
**세부 요구사항**:
- 협업 필터링(아이템-아이템): U_p = p를 꼽은 사용자 집합
  sim(p, q) = |U_p ∩ U_q| / √(|U_p|·|U_q|)
  CF_u(p) = Σ_{q∈L_u} w(r_u(q)) · sim(p, q)
- 콘텐츠 기반
  x(p) = [ 0.40·onehot(소분류) ‖ 0.25·t_맛(p) ‖ 0.15·t_분위기(p) ‖ 0.20·t_상황(p) ]
  t_g(p) = 그룹 g 태그별 부여 여부(F-19, 0/1)
  c_u = Σ_{q∈L_u} w(r_u(q)) · x̃_u(q),  x̃_u(q) = 사용자 본인이 q에 입력한 정보가 있으면 태그 부분을 본인 선택값으로 대체
  CB_u(p) = cos(c_u, x(p))
- 인기: POP(p) = S̃(p) / max S̃
- 최종: score_u(p) = α·CF̂ + (1−α)·(0.6·CB + 0.4·POP),  α = min(1, k_u / 20), k_u = 나와 리스트가 1곳 이상 겹치는 사용자 수. CF̂는 후보 내 max 정규화
- 제외: 내 리스트의 가게, 폐업, 직전 결과(F-12 "다시 추천")
- 추천 사유: CF 기여 최대 → "〈내 1위 가게〉를 꼽은 사람들이 많이 꼽은 곳", CB 최대 → "〈일치 태그〉 취향과 일치", POP 최대 → "국캠 전체 순위 〈n〉위"
- 본인 정보 입력이 많을수록 x̃가 본인 판단을 반영 → F-02 보상 설계의 근거
**완료 조건**:
- [ ] 다른 사용자가 0명일 때도 오류 없이 CB+POP 결과가 나온다
- [ ] 내 리스트에 있는 가게는 절대 추천되지 않는다
- [ ] 고정 테스트 데이터에서 점수가 수식과 일치한다

## 구현 방향

### 선택지
| | A. Next.js + Supabase + Vercel | B. React + Firebase | C. 네이티브 앱 |
|---|---|---|---|
| 개발 난이도 | 중. SQL로 순위·추천 계산이 자연스러움 | 중. 집계를 Cloud Functions로 따로 구현 | 상 |
| 지리 쿼리 | PostGIS | geohash 수동 처리 | 백엔드 별도 |
| 비용 | 초기 무료 티어로 충분 | 무료 티어로 충분, 읽기 과금 주의 | 개발자 계정비 |
| 배포 | 즉시 | 즉시 | 스토어 심사 |

**권장: A.** 순위 집계(F-08), 태그 판정(F-19), 추천(F-13)이 모두 관계형 집계로 표현된다. 사용자 수백 명·음식점 수백 곳이면 추천은 요청 시 실시간 계산으로 충분하다.

- 지도: 카카오맵 JavaScript SDK + 카카오 로컬 REST API. 도메인 등록 필요
- 인증(MVP): Supabase Auth를 쓴다 [결정]. 이메일이 필수라 아이디를 `〈login_id〉@users.mechuri.app` 형태의 내부용 주소로 변환하고 이메일 확인은 끈다. 실제 메일은 발송되지 않는다
- 결제: 1차는 `MockPaymentProvider`. 이후 PG 가입(사업자등록·통신판매업 신고 선행) 후 구현체 교체
